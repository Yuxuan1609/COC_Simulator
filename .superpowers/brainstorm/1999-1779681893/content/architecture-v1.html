FastAPI + HTMX 架构提案

统一后端 + 声明式前端，保持 Python 生态

路由结构
/ → 启动页面（Launcher）
/character → 车卡创建向导
/game → 游戏循环主界面
/editor → JSON 模块编辑器
/api/game/turn → POST 提交玩家行动
/api/game/state → GET 获取世界状态
/api/game/stream → WS 实时推送（叙事流）
/api/character/generate → POST LLM 描述生成
/api/editor/validate → POST JSON 校验
/api/editor/save → POST 保存模块文件
之前：http.server

问题

  • 两个 server 文件，端口冲突
  • 阻塞式单线程
  • 手动路由 if/else
  • 手动 CORS / JSON
之后：FastAPI

优势

  • 单一 server 入口
  • async 非阻塞
  • 声明式路由 + 自动 docs
  • 内置 WebSocket、CORS、静态文件
之前：vanilla JS DOM 操作

问题

  • 手动 createElement / appendChild
  • 状态分散在 DOM 和变量中
  • inline onclick 处理函数
之后：HTMX

优势

  • hx-post / hx-get 声明式 AJAX
  • hx-swap 自动 DOM 替换
  • hx-trigger 事件驱动
  • 服务端渲染 HTML 片段
  • 14KB，零构建步骤
