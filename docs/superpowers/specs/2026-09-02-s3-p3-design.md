## 1. F17 场景物品（scene_items）

### 1.1 数据模型

- 新结构 `scene_items: list[{kind, ref, quantity, hidden}]`：
  - `kind: "weapon" | "item"` —— 武器与物品在后端是两个通路（weapon_library vs ItemLibrary），靠 kind 字段区分。
  - `ref` —— 库引用（weapon_ref 或 item_ref；id/名称/别名三路解析，复用库 matches）。
  - `quantity: int` —— 仅 item 有意义；**武器无数量属性**（恒单件）。
  - `hidden: bool` —— true=初始不可见需搜索暴露；false=进场即可见可捡。
- 【生成端】L2 schema 场景节点增 `scene_items` 可选字段；**旧 `scene_weapons` 保留**，加载时映射进 scene_items（`{kind:"weapon", ref:weapon_ref, hidden:false}`），旧模组零迁移。生成端 prompt/schema 切换登记 §10 清单，本期不动生产端。
- 【运行时】`ScenarioWorld.scene_items: dict[scene_name, list[SceneItem]]`：
  - 从 graph node 加载（镜像 scene_weapons 现有加载通路，scenario_core.py:703-712 模式）。
  - 旧 `world.scene_weapons` 通路在加载层合并进 scene_items，**scene_weapons 运行时结构可废弃**（或保留为 scene_items 的 kind=weapon 视图，实现时取更简者，spec 层面以 scene_items 为唯一事实源）。
  - 入档：to_dict/from_dict 镜像 scene_weapons 现有序列化通路（scenario_core.py:1194/1284/1404 模式）。

### 1.2 状态机

```
hidden --搜索成功--> exposed --拾取--> 玩家背包/武器槽
                              <--丢弃-- 背包物品（丢弃落点为当前场景 exposed 条目）
```

- 搜索 = 正常回合动作（keeper 既有通路，侦查类检定，花回合推时间）。搜索成功后当前场景**全部** hidden → exposed，叙事提示「你发现了 X」。
- 单物品独立难度不做（平面暴露，YAGNI）。

### 1.3 拾取（免费动作）

- understand 层短路（镜像 R1 直接拾取通路，understand.py:35-40 模式）：输入匹配「捡/拾/拿 + 暴露物品名」→ 直接入包，**零 LLM 调用、不推时间、不消耗回合**。
- 武器 → 武器槽（现有授予通路）；物品 → ItemManager.add（库 ref 命中带 description，未命中自由文本入包）。
- 未暴露（hidden）物品点名拾取 → 短路回「你没发现这东西」类提示，不进 keeper 主回合。
- 同名多件：按名字全捡或单个？**单个**（一次一件，quantity>1 时数量减一）。

### 1.4 丢弃（免费动作，F1 拆分本期部分）

- 「丢/扔/放下 + 物品名」→ 背包/ItemManager 减一 → `scene_items[当前场景]` 增 `{kind, ref, quantity, hidden:false}` 条目。
- 武器丢弃同样支持（武器槽移除 → scene_items kind=weapon）。
- 丢弃物品跨场景持久（入档随 scene_items），可被再次拾取。

### 1.5 offer 阻塞问句废弃

- 现有搜索发现武器后的「是否拾取？（是/否）」阻塞环（finalize.py:115 / understand.py:19-33 / adjudicate.py:141-150 / keeper.py:474-489 `_grant_scene_weapons`）**整体移除**：
  - 搜索成功不再弹问句，直接 hidden→exposed + 叙事提示。
  - offer 等待态（pending offer 过期逻辑）一并清除。
- 前端：场景面板列 exposed 物品 + 固定拾取/丢弃按钮（不阻塞回合流）；CLI 走同一 understand 短路通路。前端面板属体验配套，CLI 通路为本期主体。

## 2. F19 环境修正（environment）

### 2.1 数据模型

- 场景节点（L2）增 `environment: {lighting, noise}` 可选字段：
  - `lighting: "dark" | "dim" | "normal"`（缺省 normal）
  - `noise: "quiet" | "noisy"`（缺省 quiet）
  - 两轴起步；weather/crowd 等扩展轴等真实模组需求。
- 【运行时】world 层 `environment` 随场景状态可读写，入档；当前场景 environment 变化随场景切换生效。
- 【生成端】L2 schema 加字段 + 生成 prompt 说明「黑暗/嘈杂场景标注 environment」；登记 §10，本期登记不回填生产端（与 F17 同批处理生成端时一并）。

### 2.2 修正通道（机械映射）

- `game_config.env_check_modifiers` 全局表（数值可调，P0-1 修好的检定通道承载）：
  ```json
  {"dark": {"侦查": -20, "潜行": +10, "聆听": 0},
   "dim":  {"侦查": -10},
   "noisy": {"聆听": -20}}
  ```
  （初值示例，调数值空间是设计意图：映射到**技能目标值 ±N** 而非难度升降档——2026-09-02 用户拍板）
- judge 检定结算前：`effective = clamp(1, 99, skill_value + Σ env_mod)`；模组实体显式 `difficulty` 优先，环境修正做增量叠加（不覆盖模组作者意图）。
- 无 environment 字段的场景 = 全零修正，行为与现状一致。

### 2.3 运行时变更（@env_change）

- markup 新增 `@env_change(axis="lighting", value="normal")`：
  - side_effects 通路解析 + 执行（parse_markup_all 正则加分支，scenario_core apply_side_effects 加 handler）。
  - 改当前场景 environment；叙事/事件/法术效果均可触发（开灯、起雾）。
  - 非法 axis/value → 忽略 + warning（side_effects 既有降级风格）。

### 2.4 LLM 知情层

- 当前场景 environment 标签进 keeper/enrich prompt（一行「环境：黑暗/嘈杂」），供叙事呼应；**不参与 LLM 数值裁定**（数值只走 2.2 机械通道）。

### 2.5 关键改动点

| 位置 | 改动 |

| investigator/rules.py game_config | `env_check_modifiers` 表 + 校验 |
| game/judge.py check_skill 调用点 | 掷骰前查当前场景 environment 应用修正 |
| module_designer/layered_schema.py | L2 场景节点 environment 字段 |
